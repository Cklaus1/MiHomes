# MiHomes Hardening Spec — Bug Fixes & Improvements

> **Status:** Reviewed (v2 — adversarially verified) · 2026-07-29 · **Author:** Architecture review (fable, 6-way parallel + 3-way adversarial re-verification) · **Baseline commit:** `f172a2c`
> **Scope:** Correctness, data-integrity, security, and reliability defects in the existing single-user product (`src/mihomes/`, `bridge/`, `scripts/`, `alembic/`).
> **Not in scope:** The SaaS re-platform (see `docs/product/SAAS_PRD.md`). These fixes should land on the current codebase *before or alongside* that work — the multitenant migration will inherit every one of these bugs otherwise.

## How to read this

Six reviewers swept the codebase in parallel: **AI**, **Gateways/Watchdog**, **Web**, **Services**, **Data-layer/Migrations**, **CLI/Cross-cutting**. Then three **adversarial** reviewers re-attacked the consolidated spec against source to break wrong severities, false positives, and fixes that would break other code paths. Every finding below was checked against actual source; **v2 verdicts, corrected severities, and fix corrections are folded in place** and marked ⟲ADV where the adversarial pass changed something.

Severity = blast radius × silence. A bug that silently corrupts financial data outranks one that throws a visible traceback.

### The theme: silent failure

The single most dangerous pattern in this codebase is **`except Exception: pass`** wrapping business logic. It has *already* hidden multiple critical bugs indefinitely (the nonexistent-enum bugs D3/D4, the no-op data migration H6, the nonexistent `inventory_items` table M44). Every fix below that removes a silent swallow is worth more than its line count suggests. **Cross-cutting rule R1 (below) is the highest-leverage single change in this spec.**

> ⟲ADV note on R1's framing: R1 does **not** "hide H6" (H6 is a no-op UPDATE, not an exception). And D3 is only *half*-silent — `execute_tool` returns the error text *to the model* as the tool result, so the agent sees "Tool error (query_issues): …" and apologizes/hallucinates rather than failing invisibly. Still broken; P0 stands.

## P0 — Critical (data loss, data corruption, guaranteed-crash on common paths)

### D1. Backup/restore is unsafe on WAL-mode SQLite — the biggest data-loss risk ✓VERIFIED
`services/backup.py:20-24,34-35`. DB runs in WAL mode (`db.py:21`), so committed data lives in `mihomes.db-wal` until checkpoint. `create_backup` tars **only** `mihomes.db` — no checkpoint, no `-wal`/`-shm`, no sqlite backup API — so a backup taken after recent activity silently omits the WAL contents, and copying mid-write can produce a torn/corrupt file. `restore_backup` does `tar.extractall()` over the live DB without disposing the engine or deleting the stale `-wal`/`-shm`, so SQLite replays the *old* WAL against the *restored* file — corrupting it or resurrecting pre-restore data. `extractall` also has no `filter="data"` (path-traversal from a tampered archive).
- **Fix:** Back up via `sqlite3.Connection.backup()` or `VACUUM INTO` a temp file, then tar that. On restore: dispose the engine, delete `mihomes.db{,-wal,-shm}`, extract with `filter="data"`, and snapshot the current DB first so a bad restore is reversible.
- **⟲ADV caveats:** (a) `extractall(filter="data")` needs Python ≥ 3.11.4 — pin it in `pyproject`. (b) Disposing the engine in the restoring process is **insufficient in the real deployment**: the watchdog, monitors, bridge, and web server are *separate processes* each holding their own SQLite connections; restore must stop them (or loudly document the requirement) or the stale-WAL replay can still occur from another process. Add a pre-restore "stop all services" step or refuse to restore while any pid file is live.

### D3. `IssueStatus.CLOSED` does not exist — breaks the AI's most common query ✓VERIFIED
`services/ai/tools.py:473`. `IssueStatus` has no `CLOSED` member (it's `REPORTED, ASSESSED, SCHEDULED, IN_PROGRESS, RESOLVED, VERIFIED`). `query_issues` with the default `open_only` path raises `AttributeError`. ⟲ADV: not fully silent — `execute_tool` (`tools.py:279-280`) returns the error string as the tool result to the model, which then apologizes or fabricates. The agent answering "what issues are open?" is broken either way.
- **Fix:** `Issue.status.notin_([IssueStatus.RESOLVED, IssueStatus.VERIFIED])`. **Do this in the same pass as H10/M32/M33** (one `tools.py` change) plus the R1 smoke test — see Sequencing.

### D4. `TaskStatus.DONE` does not exist — every estate digest silently omits tasks ✓VERIFIED
`services/ai/reports.py:236,245`. `TaskStatus` is `PENDING, IN_PROGRESS, COMPLETED, CANCELLED`. `TaskStatus.DONE` → `AttributeError`, swallowed by `except Exception: pass` (line 264), so `generate_estate_digest` has **never** included completed/overdue tasks.
- **Fix:** `TaskStatus.COMPLETED`. (R1 would have surfaced this on day one.)

### D5. `--demo` (and `dev()`) crash at startup ✓REPRO
`web/server.py:14-24,32-39`. `_seed_demo_db()` builds demo.db via `Base.metadata.create_all()` without stamping `alembic_version`; `init_db()` then runs `alembic upgrade head` on the same file (MIHOMES_DEMO=1 → `_active_url` returns demo.db) → `OperationalError: table audit_log already exists`. Both `main` and `dev` affected — demo mode cannot start at all.
- **Fix:** `command.stamp(cfg, "head")` after `create_all`, or seed through migrations instead of `create_all`.

### D6. Document uploads: stored XSS + unbounded size + None filename → 500 ✓VERIFIED (all four sites)
`web/routes/issues.py:167-170`, `work_orders.py:214-217`, `assets.py:435-438`, `contracts.py:115-119`. All four take the client extension (`Path(file.filename).suffix` → `AttributeError` when `filename is None`), read the whole body with no cap (`write_bytes(await file.read())`), and write under the publicly-served `static/uploads/`. `x.html`/`x.svg` becomes a same-origin script-executing page (stored XSS); multi-GB upload OOMs.
- **⟲ADV — the spec's original fix was WRONG. Do NOT "reuse `read_image_uploads`":** that helper keeps only `att.is_image` and raises `"No usable image found"` otherwise (`web/forms.py:6-29`), so it would **break every PDF invoice/contract/warranty upload** — the primary documented use of these endpoints (`doc_type` defaults to `invoice`; the UI offers Invoice/Contract/Warranty/Insurance/Permit/Report and renders PDFs).
- **Correct fix:** a new `read_document_upload` helper that whitelists images **∪ `application/pdf`** (reject `.html/.svg/.xhtml`), guards `file.filename is None`, streams to disk with a byte cap, and writes a random name (routes already use `uuid4().hex` — keep that). **The XSS is closed by the *serving* layer, not upload validation:** `app.py:43` mounts `/static` via Starlette `StaticFiles`, which sends neither `Content-Disposition: attachment` nor `X-Content-Type-Options: nosniff`. Add a custom `StaticFiles` subclass or a dedicated `/uploads/{name}` download route that sets both — an SVG that passes an image check still executes if served inline. **This finding is not "done" at the reader level.**
- **Sequence with H34 (uploads relocation) and M45 (`save-report .md` fifth writer) as one pass** — all rewrite the same write-path. See Sequencing.

### D7. `whatsapp watchdog` always crashes on Linux/macOS ✓VERIFIED
`cli/whatsapp.py:167-172,178-180,205-219`. Calls `subprocess.STARTUPINFO()` unconditionally (Windows-only) → `AttributeError` on POSIX; the pid-liveness check has the same gap. `cli/telegram.py:737-746` already has the platform-branched fix — the WhatsApp copy drifted. ⟲ADV: only `whatsapp watchdog` crashes on POSIX; `whatsapp autostart` takes a win32-only branch and is unaffected.
- **Fix:** Delete the private copies; share one `_watchdog.py` helper (see R2). Zombie/pid fix is shared with D8.

### D8. Watchdog fails its core job: dead monitors reported alive; hot-loop when unconfigured ✓VERIFIED
`scripts/watchdog.py:27-45,76-90,160-163`. Three compounding failures: (a) `_start_monitor` never reaps the `Popen`, and `_pid_running` uses `os.kill(pid,0)` which **succeeds for zombies**; (b) the Telegram monitor is restarted every 60s with no `autostart`/token gate and no backoff; (c) each restart leaks the `monitor.log` file handle → FD exhaustion.
- **⟲ADV mechanism split:** on **POSIX**, (a) *masks* (b) — the first dead monitor becomes an un-`wait()`ed zombie, `os.kill(pid,0)` succeeds forever → one silent permanent failure, not a hot-loop. The hot-loop + FD-leak is the **Windows** behavior. Both are fatal; the fix covers both.
- **Fix:** Keep the `Popen` and use `proc.poll()` for liveness (reaps in-call); gate Telegram on `telegram.autostart`+token with exponential backoff like WhatsApp; open the log with `with` so the parent copy closes after spawn. The zombie/`os.kill` bug exists in **three copies** (`scripts/watchdog.py:27`, `cli/telegram.py:688`, `cli/whatsapp.py:164-175`) — fix all three or `telegram status`/`stop` still trust zombie PIDs (Sequencing).

### Data-layer / schema

## Resolved decisions (Step 2 — canon)

Every open question in this spec is resolved below. These are **binding** for the build loop — no re-litigation mid-run; genuinely new questions go to `opportunities.md`.

- **Q1 — H8/H9 default model id.** Options: (a) `claude-sonnet-5`, (b) `claude-opus-5`, (c) keep a pinned dated Sonnet. **Decision: `claude-sonnet-5`.** It's the current-generation balanced model; the workload is tool-routing + short structured reasoning, where Opus is cost-overkill and a dated pin re-introduces the same retirement trap (H9). Define **one** module-level constant `DEFAULT_MODEL = "claude-sonnet-5"` in `ai_config.py` and import it in `claude_provider.py`; delete the two other literals. H8 and H9 land in the **same commit** (factory-forward + default-bump + the `reports.py:168,395`/`weather_tasks.py:77` call sites + remove the `agent.py:41-42` workaround).
- **Q2 — R5 money type.** Options: (a) `Numeric(12,2)`, (b) integer-cents `TypeDecorator`, (c) leave `Float`. **Decision: integer-cents `TypeDecorator`** (`type/money.py`, `Money = TypeDecorator(impl=Integer)`, Python side exposes `Decimal`/float dollars, DB stores `int` cents). `Numeric` is a no-op on SQLite (stored as float); `Float` is the root cause of M1–M4. Migration casts `CAST(ROUND(amount*100) AS INTEGER)` per column. One decorator, applied column-by-column in R4/R5.
- **Q3 — M43 `/reports` router.** Options: (a) mount + add nav, (b) delete the dead module. **Decision: delete `web/routes/reports.py` + `templates/reports.html`.** It's unreachable dead code; `budget.html` already renders the chart surface, and deleting it *removes* the harder half of H29's XSS surface rather than hardening it. If a reports page is wanted later it should be rebuilt against the live schema — captured in `opportunities.md`. **This makes H29 budget.html-only.**
- **Q4 — M44 `query_inventory`.** Options: (a) create an `inventory_items` model+migration, (b) redirect the tool to existing `Asset`+`Consumable`, (c) remove the tool. **Decision: redirect to `Asset` + `Consumable`** (the inventory data already lives there; `inventory_items` is a phantom table baked into shipped code). Rewrite `tools.py:745-815` to query the ORM models instead of raw SQL; no new table. Add it to the R1 smoke test.
- **Q5 — H2 `HaEntity`.** Options: (a) wire up (import + migration), (b) delete the dead model. **Decision: delete the dead `HaEntity` model.** Home-Assistant integration is not in Phase 1a scope and nothing references it at runtime; a migration for an unused table is pure liability. Capture "HA entity sync" as a future feature in `opportunities.md`. (Downgraded to P3 already; deletion happens in R4.)
- **Q6 — M36 provider tool-loop refactor.** Options: (a) do the full `stream_with_tools()` protocol refactor in this run, (b) defer. **Decision: defer to `opportunities.md`.** It's a genuine architecture change with no P0–P2 finding that *requires* it — the immediate provider defects (H8 model-forward, H11 final-call, H13 image capability, M35 content handling) are fixed independently.
